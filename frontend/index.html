Module 0 — Kickoff

15 min  |  Concept overview — no code written by participants yet.

The Physical AI pipeline

Physical AI is the discipline of building systems that perceive the physical world through sensors, reason about that world, and act on it through actuators — closing the loop between sensing and doing.

Every module today builds one piece of this pipeline. By Module 4, the full loop is closed: your hand gesture changes the simulation, which changes what the next frame looks like.

[Webcam] → [Perception Layer] → [State Vector] → [Sim Agent] → [Action] ↑ ↓ [World/Sim] ←───────────────────────────────────────────────── [Effect] ↑ [Foundation Model Reasoning]

The loop is closed: every action changes the simulated world, which changes what the camera sees next. This closed-loop property is what distinguishes Physical AI from static inference tasks.

The state vector

The state vector is the central data structure of the pipeline — a compact numeric array that encodes everything the agent needs to know about the world at one instant. It bridges perception (raw sensor data) and control (the action the agent takes).

Module 1 — Perception

How perception works

A camera frame is processed by MediaPipe's Hand Landmarker model, which returns 21 normalised landmark coordinates per hand — each in the [0, 1] range. From three pairs of landmarks we compute a joint angle using a dot-product formula, producing a compact state vector the rest of the pipeline can act on.

Everything in this module runs entirely in the browser — no server needed. The MediaPipe WASM bundle and model are loaded from CDN on first use.

State vector

—

[θ_thumb, θ_index, θ_middle] in degrees

Angles are the MCP joint opening angle for each finger — 0° = fully closed, ~180° = fully open.

Sim-to-real transfer

Policies trained entirely in simulation — like the PPO agent from Module 3 — can be deployed on real hardware if the simulation is faithful enough to the physical world. The gap between simulated and real dynamics (the sim-to-real gap) is narrowed by domain randomisation: training across randomised mass, friction, and sensor noise distributions so the policy generalises rather than overfitting to one set of physics parameters.

Digital twins take this further — a continuously updated high-fidelity simulation that mirrors a specific physical asset in real time. Sensor readings from the real robot are fed back into the simulation to keep it synchronised, enabling safe policy evaluation and predictive maintenance without touching the hardware.

What to explore next

  • Isaac Lab — NVIDIA's GPU-accelerated robot learning framework built on Isaac Sim; runs thousands of parallel MuJoCo-quality environments for fast sim-to-real transfer.
  • LeRobot — HuggingFace's end-to-end imitation learning library; the natural next step after Module 4's teleoperation, turning your demonstration data into a trained Diffusion Policy or ACT policy.
  • ROS 2 — the Robot Operating System; the industry-standard middleware for connecting perception, planning, and actuation nodes on real hardware across a distributed network.
